# Diagnóstico — i18n (Tradução / Multi-idioma)

> Checklist a rodar sempre que uma tela for criada ou alterada (ver `patterns/padrao-i18n.md` para o padrão completo por trás de cada item). Também roda como parte do Modo Enterprise (`SKILL.md`) para qualquer tarefa que toque `app/Views/`.

## Checklist

- [ ] **Nenhum texto hardcoded em view nova/alterada**: todo texto visível ao usuário passa por `t('modulo.tela.elemento')`, nunca string literal direto no HTML/PHP da view.
- [ ] **Nenhuma chave só em um idioma**: toda chave usada existe nos 3 arquivos (`lang/pt_BR.php`, `lang/en.php`, `lang/es.php`) — rodar o script de paridade abaixo antes de considerar a tela pronta.
- [ ] **Escaping correto por contexto**: `htmlspecialchars(t(...))` em HTML normal; `addslashes(t(...))` dentro de atributo JS (`onsubmit`, `onclick` etc.) — nunca `t()` cru sem escaping em nenhum dos dois contextos.
- [ ] **Enum do banco não usa `ucfirst()` cru**: se o texto exibido vem de uma coluna enum (`status`, etc.), tem um mapa `valor => t('modulo.status.valor')` com fallback, não `ucfirst($valor)` direto (ver `patterns/padrao-i18n.md`).
- [ ] **Fallback testado**: remover temporariamente uma chave de `en`/`es` (ou usar uma chave inexistente) e confirmar que a tela não quebra — deve cair no texto em pt_BR ou, na ausência total, mostrar a própria chave (nunca erro fatal).

## Script de paridade de chaves (rodar antes de commitar)

```bash
php -r '
$files = ["pt_BR" => "lang/pt_BR.php", "en" => "lang/en.php", "es" => "lang/es.php"];
$keys = [];
foreach ($files as $locale => $path) { $keys[$locale] = array_keys(require $path); }
$all = array_unique(array_merge(...array_values($keys)));
$ok = true;
foreach ($all as $k) {
    $missing = [];
    foreach ($keys as $locale => $ks) { if (!in_array($k, $ks, true)) $missing[] = $locale; }
    if ($missing) { $ok = false; echo "FALTANDO em [" . implode(",", $missing) . "]: $k\n"; }
}
echo $ok ? "OK: todas as chaves existem nos 3 idiomas (" . count($all) . " chaves)\n" : "FALHOU: paridade quebrada\n";
'
```

Saída esperada: `OK: todas as chaves existem nos 3 idiomas (N chaves)`. Qualquer linha `FALTANDO em [...]` precisa ser corrigida antes do commit.

## Como testar trocando o idioma de um Negócio

1. Editar o Negócio em `/platform/negocios/{id}/edit`, aba "Plano" → campo "Idioma padrão deste Negócio" → trocar para Inglês ou Espanhol → salvar.
2. Impersonar esse Negócio (`/platform/negocios/{id}/impersonate`) ou logar como usuário dele.
3. Abrir uma tela já migrada (hoje: `/platform/negocios`, só acessível como superadmin — para testar como usuário do tenant, usar uma tela migrada futura que seja tenant-facing) e confirmar que os textos mudaram de idioma.
4. Voltar o idioma para `pt_BR` e confirmar que volta ao original — nenhuma regressão para negócios que nunca mexeram nesse campo (default `pt_BR` na migration cobre isso).

## Sem banco de dados disponível (CI/ambiente local sem MySQL)

`App\Core\Translator` não depende de banco — só de `TenantContext`/sessão para saber qual idioma usar, e de `require` dos arquivos `lang/*.php`. É possível validar a troca de idioma e o fallback isoladamente:

```bash
php -r '
require "app/autoload.php"; require "app/helpers.php";
define("BASE_PATH", getcwd());
use App\Core\Translator;
foreach (["pt_BR","en","es"] as $l) { Translator::setLocale($l); echo "$l: " . t("negocios.index.titulo") . "\n"; }
Translator::setLocale("xx"); echo "invalido->fallback: " . Translator::locale() . "\n";
'
```
